# Synthetic-data provenance

## Source and generation

All seven files in `data/synthetic/` are produced by
`src/research_ops_architecture/synthetic.py`; field order is defined by `models.py`.
The generator performs no file input, network lookup, document extraction, or
random sampling. It uses a fixed default reference date of 2026-07-01 and fixed
lifecycle paths. Labels are deliberately fictional:

- `SYN-REVIEW-0001` through `SYN-REVIEW-0012` are local demo keys, not publisher IDs.
- `Synthetic review topic 01` through `12` contain no source-derived titles.
- `Demo Author 01` through `12` are placeholders, not people or pseudonymized records.
- Request, author-approval, event, reminder, and document keys are loop-generated.
- Date offsets, approval counts, and status choices are arithmetic fixture rules.
- Document rows are metadata only. There are no forms, manuscripts, emails,
  credentials, signature links, contact addresses, or source exports.

The release preparation replaced the baseline's realistic name/topic literals and
publisher-style review IDs to avoid mistaken identification. This is generated
fiction, not de-identification of operational records. Workflow terminology and
schemas model a generic process; no institutional affiliation is implied.

## Verify

Run `PYTHONPATH=src python3 scripts/demo.py` from the repository root. It compares
every committed CSV to freshly generated bytes and checks two independent runs
for equality. The CLI can regenerate the files and quality report.

Freshness checks use the fixed fixture date. These rows are not observations of
current workflow performance. Some date sequences are simplified and internally
unrealistic: a generated document may precede the request completion date, and
cancelled requests can retain synthetic author-sent/approved rows. The validators
do not certify full business-process consistency or clinical validity.

## Rights scope

The proposed project MIT licence covers these generated fixtures as part of the
sample. No external dataset licence is needed for an imported corpus because
none is included. This provenance describes inspectable generation, not a blanket
assurance about every possible third-party right.
